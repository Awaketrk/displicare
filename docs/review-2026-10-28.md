# Code review and UX notes (2026-10-28)

## Changed in this pass (uncommitted, all 83 tests pass, not tried on hardware yet)

| Change | Why |
|---|---|
| Shell hook ignores title redraws, taskbar flashes, media keys and language switches (`IsGammaRelevantShellEvent`) | Every shell event started a burst of six gamma-ramp read-backs. Apps that update their title often (browsers, players, timers in the title) kept that going non-stop. Activation, new windows, fullscreen games and monitor moves still trigger it, and the 1.5 s watchdog covers the rest. |
| Removed `_foregroundReassertTimer` | Created at startup, never started anywhere. |
| `MonitorEngine.WriteBaseline` replaces the two copies of "write baseline or linear ramp" (`ResetGammaRamp`, `RestoreOriginalGamma`); `LinearRamp()` used in the four places that built it by hand | Less duplicated ramp code; same behaviour. |
| Fixed a doc comment that sat on `MonitorKeyFromId` instead of `IsVirtualAdapter` | It described the wrong method. |
| Reset All queues the DDC/CI backlight write instead of doing it on the UI thread | Each DDC/CI write takes tens of ms per monitor; the window froze briefly on reset. |
| `ApplyCurrentSettings`, `BuildMonitorRows`, display selection read `_engine.Displays` once | The property copies the whole list on every access, several times per slider tick. |
| `app.log` lines carry the date (`yyyy-MM-dd HH:mm:ss.fff`) | The log spans days; with only a time it's hard to tell which day a line belongs to. |

## UX ideas, roughly by value

1. **Brightness without opening the window.** Mouse wheel over the tray icon, and optional global hotkeys (e.g. Ctrl+Alt+Up/Down) with a small on-screen brightness note like the room note. That's the most common action, and today it needs a click, a drag and a click away.
2. **One way to pick "all displays" vs one.** The "Sync All / Separate" toggle and the "All displays" entry in the target list mean the same thing and switch each other. Keep one, or show a slider per monitor in the flyout (each card with its own brightness), with a link icon to tie them together.
3. **Reset All asks first, or offers Undo.** It sits right next to Minimize, resets brightness, colour and gamma on every screen and saves at once. A "Reset? Undo" note for a few seconds would be gentler than a dialog.
4. **Solar Sync resumes by itself.** A manual slider move stops it until "Resume" is clicked. Resuming at the next sunrise or sunset (or after a set time) would match what people expect from Night Light.
5. **Location in the UI.** Today exact coordinates need a hand edit of `settings.json`. A latitude/longitude field (or a city search with a small built-in list) in the Solar schedule panel.
6. **Per-monitor software floor.** The 30% (SDR) and 8% (HDR) floors were tuned on the AORUS; other screens may want lower or higher. A "lowest brightness" slider on each display card in the Displays tab.
7. **Per-app profiles.** The foreground hook already knows which app is in front: optional "when this app is in front, use this preset" (e.g. Gaming FPS for a game, Paper Read for a reader). Reading the foreground window only, no injection, so it's safe with anti-cheat.
8. **Follow the Windows theme.** The window is always dark purple. Following light/dark mode and the accent colour would make it look native on Windows 11.
9. **Update check on the About card.** An opt-in "Check for updates" that reads the latest GitHub release and links to it.
10. **Settings export/import.** A button pair on the About card for moving calibrations and rooms to a new PC or reinstall.
11. **First-run hint for DDC/CI.** When a monitor doesn't answer DDC/CI, the card could say "Turn on DDC/CI in the monitor's menu for real backlight control" right there, not only in the README.

## Code health, not changed

- `SaveRampState` writes the 3 KB ramp file on every slider tick while a software-dimmed display is dragged (for crash safety). It works; debouncing it to the end of a drag would save disk writes, but a crash mid-drag would then restore an older ramp.
- `MainWindow` still builds the display cards in code with hard-coded colours. Moving the colours to resources in `MainWindow.xaml` would make a theme change (idea 8) much easier.
- Many `catch { }` blocks swallow errors silently around Win32 calls. Logging the rare ones (gamma write refused, DDC/CI write failed) would make user reports easier to read.
